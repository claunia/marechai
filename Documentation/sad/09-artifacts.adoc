= Artifacts

The purpose of this section is to describe the various artifacts that are stored in the system's database. Each artifact corresponds to a database table (or Entity Framework Core model). All text is written in American English (_en-US_) and Latin script by default.

NOTE: The system administrator may choose a different language as the primary text language.

NOTE: When an Id field is not specified, or any other specified field is marked as a primary key, it is implicit that the artifact requires such a field for storage in the database.

NOTE: Field types in _cursive_ represent links to another artifact.

NOTE: All artifacts inherit `CreatedOn` and `UpdatedOn` timestamp fields from the base model class, which are omitted from the tables below for brevity.

This artifact represents books about computing.

| Pages | Short | Number of pages.
| Edition | Int | Edition number.
| Previous | _FK_ | Link to previous edition, if applicable.
| Next | _FK_ | Link to next edition, if applicable.
| Source | _FK_ | If this book is a derivative (e.g. translation) of another, link to the original.

| Companies | _FK[]_ | Companies associated with this book.
| People | _FK[]_ | People associated with this book.

=== Hardware by machine junction artifacts

The following junction artifacts link hardware components with machines:

* *GPUs by machine*: Links a GPU with a machine.
* *Processors by machine*: Links a processor with a machine, including the clock speed in MHz at which the processor runs in that machine.
* *Memory by machine*: Links memory with a machine, specifying type, usage, size, and speed.
* *Storage by machine*: Links storage with a machine, specifying type, interface, and capacity.
* *Sound synthesizers by machine*: Links a sound synthesizer with a machine.
* *Screens by machine*: Links a screen with a machine.
* *Software platforms by machine*: Links a software platform with a machine.

== Import Staging Tables

The following artifacts are used exclusively by the data import pipelines for staging imported data before promotion to core domain entities. They are described in summary form, as they represent internal ETL state rather than public-facing domain entities.

=== MobyGames staging

* `MobyGamesDiscoveredGame`: Stores discovered game metadata with import status.
* `MobyGamesImportState`: Tracks overall import progress and configuration.
* `MobyGamesCoverDownloadState`, `MobyGamesPromoArtDownloadState`, `MobyGamesScreenshotDownloadState`: Track per-asset download progress.
* `MobyGamesVideoImportState`, `MobyGamesReviewImportState`: Track video and review import progress.
* `MobyGamesRejection`: Records games explicitly rejected from import.

=== WinWorld staging

* `WwpcSoftware`: Stores crawled software entries from WinWorldPC.
* `WwpcVersion`: Version information for WinWorld software.
* `WwpcCategory`: WinWorld category classifications.
* `WwpcScreenshot`: Screenshots from WinWorld entries.

=== OldDos staging

* `OldDosSoftware`: Stores crawled software entries from old-dos.ru.
* `OldDosVersion`: Version information.
* `OldDosCategory`: Category classifications.
* `OldDosOsPlatformMap`: Maps old-dos.ru OS/platform identifiers to Marechai platforms.
